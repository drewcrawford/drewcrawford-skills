# doctest evaluation

We need to evaluate our doctests to see if they comply with policy.

Before leaving Rust doctests as `no_run` or `ignore`, try to make them runnable.
For doctests that need a WASM/browser test environment, first follow
[`wasm_lite`'s testing guide](https://github.com/drewcrawford/wasm_lite/blob/main/docs/testing.md),
including its doctest runner setup and async-doctest guidance. Only fail this
checklist step and escalate to the user after that approach does not make the
doctest runnable; report what you tried and why it still cannot run.

```bash
grep -R --include '*.rs' -n -E '```[^`]*\b(no_run|ignore)\b' .
```

# no_run doctests

All norun doctests should have an explanation in a hidden comment for why they are no_run:

```rust
# // no_run because: feature XYZ is not supported in a doctest
```

If any test lacks such an explanation, fail the checklist here and escalate to the user.

# ignore doctests

Ignore doctests are typically non-Rust code (i.e. ASCII diagrams or tables).

If an ignore test appears to be Rust code, it should have an explanation in a hidden comment for why it is ignore:

```rust
# // ignore because: Reason
```

If any test lacks such an explanation, fail the checklist here and escalate to the user.
